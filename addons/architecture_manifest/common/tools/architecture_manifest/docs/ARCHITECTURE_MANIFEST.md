# Architecture manifest contract

## Concept

An architecture manifest is a closed, content-minimized description of a
system's structure that lives in the repository next to the code it describes.
It is authored by hand (or generated by a separately reviewed tool) and is the
single source of truth from which human-readable architecture artifacts are
rendered. Because rendering is deterministic, a rendered diagram can be checked
back against the manifest in CI: if they disagree, the diagram is stale.

The design goal is a diagram that cannot silently drift from reality and cannot
leak infrastructure detail. Both properties come from the same decision: the
manifest holds only opaque tokens, finite enums, and repo-relative evidence
paths.

## Provenance basis (neutral standards)

The vocabulary is derived independently from Firestarter/Auggie architecture
needs and neutral public standards, cited here rather than any third-party
implementation:

- **W3C PROV** (https://www.w3.org/TR/prov-overview/): components and data
  stores are entities; owner roles are attributions (`wasAttributedTo`);
  dependencies are relations. PROV derivation (`wasDerivedFrom`) is a partial
  order, which is why `depends-on` and `derives-from` edges must be acyclic
  while runtime relations (`calls`, `reads`, ...) may cycle.
- **JSON Schema 2020-12**: every contract in `schemas/` is a closed object
  (`additionalProperties: false`) kept in lockstep with the Python enums.
- **General Mermaid / graph conventions**: inform the render layer only.

## Schema

`schemas/architecture-manifest-1.0.schema.json` is the manifest contract.
Top-level keys: `schemaVersion`, `manifestId`, `trustBoundaries`, `components`,
`dataStores`, `dependencies`.

| Entity | Closed vocabulary |
| --- | --- |
| Trust boundary tier | `public`, `perimeter`, `internal`, `restricted`, `isolated` |
| Component kind | `service`, `library`, `job`, `gateway`, `ui`, `cli`, `adapter`, `external-system` |
| Data store kind | `relational`, `document`, `key-value`, `graph`, `object-store`, `cache`, `search-index`, `queue`, `secret-store` |
| Dependency relation | `calls`, `reads`, `writes`, `publishes`, `subscribes`, `depends-on`, `derives-from` |
| Owner role | `platform`, `application`, `data`, `security`, `integration`, `unassigned` |
| Data class | `public`, `internal`, `confidential`, `regulated` |
| Evidence kind | `doc`, `test`, `schema`, `config`, `diagram`, `runbook` |

Every identifier and name is an opaque token matching
`^[A-Za-z0-9][A-Za-z0-9_.:-]{0,95}$`. Every evidence path is repo-relative,
matching `^[A-Za-z0-9][A-Za-z0-9_./-]{0,199}$`, with an optional
`sha256:<64hex>` digest. Absolute paths, `..` traversal, URLs, hosts, and
identity-shaped values are rejected.

The drift report (`schemas/render-drift-report-1.0.schema.json`) and the render
envelope (`schemas/manifest-render-envelope-1.0.schema.json`) complete the
schema set.

## Validation rules (fail-closed)

`load_manifest` rejects a manifest with a closed `ManifestErrorCode`:

- `empty-manifest`, `unknown-field`, `missing-field`
- `invalid-id`, `unknown-enum`, `invalid-digest`
- `absolute-path`, `identity-leak` (evidence path leaks)
- `missing-evidence` (a component or data store with no evidence link)
- `duplicate-id` (ids must be unique across all entities)
- `unresolved-reference` (boundary, endpoint, or a self-loop)
- `cyclic-dependency` (`depends-on` / `derives-from` must be a DAG)
- `bound-exceeded` (entity counts past the policy bounds)

## Usage

```python
import json
from tools.architecture_manifest import (
    load_manifest, render_mermaid, render_anatomy, check_drift,
)

manifest = load_manifest(json.loads(open("architecture.json").read()))
mermaid = render_mermaid(manifest)      # deterministic flowchart TD
table = render_anatomy(manifest)        # deterministic Markdown tables

report = check_drift(manifest, open("ARCHITECTURE.mmd").read(), "mermaid")
assert report.is_current, report.to_contract_dict()
```

## Drift workflow

1. Commit the manifest and its rendered artifacts together.
2. In CI, re-render from the manifest and run `check_drift` against the
   committed artifact. A `stale` verdict fails the build; the fix is to
   re-render and commit, or to correct the manifest.
3. `malformed` is returned for an invalid manifest, an unknown artifact kind,
   or non-string artifact text. It is never a false `current`.

Comparison is by normalized content (unified line endings, per-line trailing
whitespace stripped, trailing blank lines dropped, then SHA-256), so reflowing
whitespace or changing EOLs does not trip drift, while any semantic change does.

## Boundaries

The add-on never reads a real codebase, never crawls an AST, never touches the
network or a subprocess, and never runs a model. It emits no absolute paths and
holds no identity. It produces reviewable artifacts and a drift verdict; acting
on them stays a human/CI decision.
